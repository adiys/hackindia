# HackIndia 2026–27 — Judging Criteria

At HackIndia hackathons, judges evaluate the **quality, originality, technical execution, and presentation** of each project.

> **Important:** The exact judging format, presentation time, Q&A duration, and scoring rubric may vary by event. If your specific HackIndia event publishes an official rubric, **that rubric takes priority**.

## 🎤 Presentation & Q&A

For events using the National Finals-style format, teams should be prepared for:

- **4 minutes** to present the project on stage
- **4 minutes** of Q&A with the judging panel

Use the presentation time efficiently. A strong pitch should quickly communicate:

**Problem → Users → Solution → Demo → Technology → Innovation → Impact → Future**

### Recommended 4-Minute Pitch

| Time | What to cover |
|---|---|
| **0:00–0:30** | Problem and why it matters |
| **0:30–1:00** | Target users and existing gap |
| **1:00–2:00** | Solution and key innovation |
| **2:00–3:00** | Working demo / prototype |
| **3:00–3:30** | Technology and architecture |
| **3:30–4:00** | Impact, scalability, and closing |

### Q&A Preparation

Be ready to answer:

- Why did you choose this problem?
- What makes your solution different?
- Why did you choose this technology?
- How does the architecture work?
- What part did your team build?
- How did you test the system?
- What are the current limitations?
- How would you scale it?
- What is the business or real-world impact?
- What would you build next?

## 🏆 Core Judging Categories

A common HackIndia-style scoring structure uses **three major categories**:

| Category | Description | Weightage |
|---|---|---:|
| **Innovation & Originality** | How unique, creative, and impactful is the idea? Does it solve a real-world problem or push the boundaries of what is possible? | **33%** |
| **Technical Implementation** | How well is the solution executed? Consider code quality, architecture, feasibility, use of technology, and whether the prototype/demo actually works. | **34%** |
| **Presentation & Clarity** | How effectively did the team communicate their idea and solution? Was the problem, solution, and impact explained clearly within the given time? | **33%** |

### 1. 💡 Innovation & Originality — 33%

Judges may consider:

- Originality of the idea
- Creativity of the approach
- Novel use of technology
- Clear differentiation from existing solutions
- Strength of the problem-solution fit
- Real-world relevance
- Potential impact

**Strong projects don't just use new technology — they use technology to solve a meaningful problem in a better way.**

### 2. ⚙️ Technical Implementation — 34%

Judges may consider:

- Working prototype
- Code quality
- System architecture
- Technical feasibility
- Appropriate technology selection
- Integration of APIs, AI, Web3, IoT, cybersecurity, or other technologies
- Reliability and testing
- Performance
- Security
- Scalability
- Quality of the implementation

A project with an attractive idea but a non-working prototype should not be presented as production-ready.

### 3. 🎯 Presentation & Clarity — 33%

Judges may consider:

- Clear explanation of the problem
- Clear explanation of the solution
- Quality of the demonstration
- Team communication
- Technical clarity
- Effective storytelling
- Ability to explain innovation and impact
- Ability to answer questions
- Staying within the allotted time

## 📊 Additional Evaluation Factors

Depending on the event, judges may also consider the following:

| Factor | What judges may look for |
|---|---|
| **Problem & Impact** | Is the problem real, important, and clearly understood? |
| **User Experience** | Is the product intuitive and easy to use? |
| **Technology Use** | Is the selected technology used meaningfully rather than only for marketing? |
| **Scalability** | Can the solution grow beyond the hackathon prototype? |
| **Security** | Does the solution protect users, data, and infrastructure? |
| **Feasibility** | Can the solution realistically be implemented? |
| **Demo Quality** | Does the prototype demonstrate the core functionality? |
| **Completeness** | How much of the proposed solution is actually implemented? |

# 🚀 How to Score Better

## 1. Show, Don't Just Tell

A working demo is more convincing than a long slide deck.

Show the most important feature early and avoid spending the entire presentation on background information.

## 2. Demonstrate Real Technical Work

Explain:

- System architecture
- Technologies used
- APIs and integrations
- AI/ML models
- Smart contracts
- Hardware components
- Database design
- Security mechanisms
- Testing methodology

## 3. Quantify Your Results

Whenever possible, provide measurable results:

- **Accuracy:** 94%
- **Latency:** 120 ms
- **Time saved:** 60%
- **Cost reduction:** 35%
- **Detection rate:** 96%
- **Energy saved:** 20%
- **Users tested:** 100+
- **Transactions processed:** 1,000+

Use actual test results rather than unsupported claims.

## 4. Explain Your Technology Choices

Be prepared to answer:

> Why this technology?

> Why this architecture?

> Why this model?

> Why this database?

> What happens when the number of users increases?

> What happens if the network goes down?

## 5. Be Honest About Limitations

Don't claim that a prototype is production-ready if it isn't.

Clearly explain:

- What is completed
- What is partially implemented
- What is simulated
- Current limitations
- Future improvements

Understanding limitations demonstrates technical maturity.

# 🧪 Demo Checklist

Before presenting, verify:

- [ ] Application starts correctly
- [ ] Hardware is powered and connected
- [ ] Internet/API connections work
- [ ] Database is available
- [ ] AI model/API works
- [ ] Smart contracts are deployed if required
- [ ] Demo account is ready
- [ ] Test data is prepared
- [ ] Backup/demo video is available
- [ ] GitHub repository is accessible
- [ ] README is complete
- [ ] No API keys or passwords are exposed

### Always have a backup

If your live demo depends on internet connectivity, APIs, cloud services, or hardware, keep a **recorded demo or backup workflow** ready.

# ❓ Questions Judges May Ask

### Problem
1. What exact problem are you solving?
2. Who experiences this problem?
3. How did you validate the problem?

### Solution
4. Why is your solution better than existing alternatives?
5. What is your unique innovation?
6. Which feature provides the most value?

### Technical
7. Why did you choose this technology stack?
8. How does your architecture work?
9. How did you test the system?
10. What happens at scale?
11. What are the security risks?
12. What are the current technical limitations?

### Impact
13. Who will use this solution?
14. How much time/cost does it save?
15. Can it be deployed in the real world?
16. What is the future scope?

### Team
17. What did each team member contribute?
18. Which parts were built during the hackathon?
19. What would you improve if you had more time?
